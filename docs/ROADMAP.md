# 上线差距与路线图（基于 v1.5.1）

这份文档回答一件事：**现在离「真的能上线收钱送电」还差什么。**  
v1.5.x 已经有演示闭环 + 可部署后端骨架；下面按优先级切开。  
「代码可做」指仓库里能继续写；「需人工」指微信认证、商户号、域名备案、桩厂商对接等，再写代码也绕不过去。

---

## P0 — 不上就没法正式营业（阻断）

| 缺口 | 类型 | 说明 |
| --- | --- | --- |
| 微信小程序认证 + 经营类目 | 需人工 | 测试号不能对外发布；充电属经营类，通常要资质与主体认证 |
| request 合法域名 + HTTPS | 需人工 | 正式环境必须关掉 `urlCheck: false`，API 走备案域名与 TLS |
| 真实 AppID / AppSecret | 需人工 | 配进服务器环境变量；**绝不能**写进小程序包 |
| 微信支付 JSAPI | 需人工 + 代码 | 商户号、证书、APIv3、回调验签、退款/对账。当前 `method=wechat` 故意返回未配置 |
| 充电桩/场站真实遥测 | 需人工 + 代码 | 现在是 60 倍速仿真曲线，没有 OCPP/云快充等通道就不能控真枪 |
| 用户协议 / 隐私政策（提审材料） | 代码可做 ✓ 本轮已补 | 小程序审核会查；本仓库已加静态页与首次同意 |

没有商户号和域名时，**不要**指望把 `dataSource` 默认改成 remote 就算上线。

## P1 — 强烈建议，上线前后尽快做

| 缺口 | 类型 | 说明 |
| --- | --- | --- |
| 数据库替换 JSON 文件 | 代码可做 | 单机 `store.json` 不能多副本；上量前换 PostgreSQL/MySQL，领域层可保住 |
| 备份与恢复演练 | 代码可做 ✓ 本轮已补脚本 | `npm run backup`；仍需你在机器上挂定时任务与异地拷贝 |
| 观测：指标 / 告警 / 集中日志 | 代码可做 | 现有访问日志已结构化；缺 Prometheus/Sentry 一类接入 |
| 发票走真实通道 | 需人工 + 代码 | 现只写本机开票记录 |
| 客服与工单 | 需人工 | 热线是演示文案 |
| 运营后台（调价、下架站、对账） | 代码可做 | 当前没有 B 端 |
| 真机全链路验收 | 需人工 | 模拟器过不了支付、扫码摄像头、弱网 |
| 密钥进 KMS / 密管 | 需人工 | `JWT_SECRET`、`WX_SECRET` 不要长期躺在明文 `.env` |

## 仓库里已经具备的（别重复造）

- 小程序完整 Demo：找站 → 扫码 → 充电 → 结算 → 订单（默认 local）
- `server/`：文件持久化、JWT 登录、`code2session` 预留、限流、Docker、优雅退出
- `docs/PRODUCTION.md`：部署与微信支付接入清单
- CI：`npm run check` + smoke + 镜像健康检查

---

## 建议推进顺序

1. **人工**：认证小程序 → 域名 HTTPS → 配 AppID/Secret → 合法域名  
2. **代码**：接微信支付回调（替换现在的 501 分支）→ 真机支付回归  
3. **人工 + 代码**：选桩协议/云平台 → 换仿真为真实启停与电量上报  
4. **代码**：JSON 持久化换数据库 → 备份告警 → 运营后台最小集  

更细的服务器操作步骤见 [PRODUCTION.md](./PRODUCTION.md)；演示验收见 [DELIVERY.md](./DELIVERY.md)。
